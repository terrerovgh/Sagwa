# Aceptación solicitada por el usuario

Actuar como arquitecto de software embebido y diseñador Edge-AI para ESP32-S3/M5Stack CoreS3, LVGL, audio I2S y orquestación híbrida. Reestructurar Sagwa 0.2.0 hacia un compañero interactivo comercial. Entregar arquitectura técnica, esquemas modulares y código C++/ESP-IDF o Arduino optimizado.

2. SkinManager desacoplado, hot-reload microSD/SPIFFS. Diez modos: mascota/ronroneo, enfoque/Pomodoro, telemetría CPU/RAM/Wi-Fi/batería, noche/PWM/silencio, centinela/sacudidas/ruidos, terminal retro/logs, multimedia/FFT/orejas/cola, trabajo/avatar en esquina/canvas, clima/entorno, error/recuperación. SagwaPluginInterface, JSON y factories C++ para inyectar widgets, skins y secundarias.
3. Wake word «Sagwa» 100% local mediante ESP-SR/WakeNet; el usuario menciona ES8388, pero la implementación debe corregir el hardware a ES7210/AW88298 del CoreS3. Maullido local inmediato antes de sockets, objetivo <100 ms; purr continuo al acariciar, queja por sacudidas FT6336U/BMI270.
4. LLMRouter local evalúa complejidad, conectividad y contexto: capa 0 mecánica/hardware/emociones sin red; OpenRouter HTTPS/WebSocket standalone cuando PCs apagados; rigs privados Mac mini/TUF con Muse/Codex/Grok/OpenCode; adapters API OpenAI/xAI/Gemini/OpenCode y contratos futuros OAuth/tokens cifrados para flujos de proveedor permitidos. No inventar acceso de suscripciones/API.
5. Entregables: diagrama FreeRTOS UI/Audio/Sensor/Router/Network y colas/EventGroups; código modular de FSM/LVGL, SkinManager, skin_template.json y .h, I2S/WakeNet/playback prioritario, LLMRouter; guía de compilación, NVS/LittleFS o SPIFFS/OTA y credenciales.

Restricciones vigentes de la interfaz: negro puro, texto blanco Inter/español, Sagwa transparente, emoji fijo a la derecha y respuestas concisas con detalle ampliado. Gestos desde bordes; PWR para voz, avatar nunca zona de grabación. Confirmación explícita para cancelación y autorización. Muse sigue como principal; sensores no ejecutan comandos en hosts.
