# Correcciones del dictamen producto B

Dictamen Grok4.7: FAIL, sesión01a13357-d704-7d31-b4c8-c122c5fade1d. Alcance estático; no ejecutó tests ni hardware. Se conserva íntegro en review-product-b.txt.

1. El Core emite decision:approve/deny; el gateway conserva task_id en errores y devuelve approval.result correlacionado. No hay confirmación optimista. UI mantiene el texto inmutable de la acción, espera ACK y conserva el diálogo ante cola llena/error. El gateway comprueba dispositivo propietario, foreground padre y tarea activa antes de registrar consentimiento. Las respuestas normales no pueden cambiar el texto asociado al hash.
2. BSP PMU y expansor se inicializan una sola vez antes de las tareas; Sensor toma el handle BSP prestado. Voltaje y RMW LDO usan mutex. Verificación adicional del driver oficial local IDF6.0.1, esp_driver_i2c/i2c_master.c:1166: no existe rechazo por dirección duplicada; su premisa de exclusividad de dirección no se reproduce en esa fuente. La centralización sí elimina duplicación/carrera de lazy-init y mantiene un propietario único. No se cambian pines ni máscaras LDO del fabricante. Se corrige además el parámetro enable ignorado: desactivar elimina únicamente los bits de la función solicitada en el mismo RMW protegido; no mantiene encendida una función al pedir voltaje cero.
3. Un corte de voz tiene revisión atómica propia: nuevos cortes del mismo turno no se pierden; se limpia el speaker una vez por corte y se cancela streaming. Activar voz explícitamente limpia el latch; preferencias remotas solo lo cambian si cambia voice_enabled. Durante un clip cancelado no se acepta un audio.start retrasado ni PCM antiguo. No se incrementa el turno al interrumpir solo voz; PWR para una nueva captura sí lo incrementa. El audio cancelado no puede reaparecer automáticamente por un evento viejo.

Pruebas de UI adicionales: tap corto no autoriza; cola llena no cierra el diálogo; texto de tarea no sustituye acción; long-press espera ACK; ACK fallido mantiene diálogo; negar espera ACK; voz off/on limpia el corte. Son LVGL/RTOS fixtures del host, no audio ni PMU físicos. La revisión nueva y validación física siguen pendientes.
